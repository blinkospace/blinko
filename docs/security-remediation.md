# Security remediation

This patch targets the public 1.8.8 source at `b2586d03fddb796252f050a96922879bf4a41fad`. It consolidates overlapping reports by root cause. It has not been deployed or published and does not assign CVE IDs.

| Area                          | Resulting behavior                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Account linking               | A nonempty, verified password for the target local account is mandatory. Self-linking and linking to passwordless OAuth accounts are rejected. Only the target account owner can unlink identities.                                                                                                                                                                                                                                                    |
| Provider/model administration | Global provider/model changes, connection tests and provider discovery require superadmin. Ordinary model-selection responses remove provider keys, URLs, provider configuration and model configuration. `/v1/config/ai` requires superadmin.                                                                                                                                                                                                         |
| Conversations/messages        | Every affected message read, write and bulk deletion checks conversation ownership. Database mutation filters also include the owner relation. Superadmin does not inherit access to another user's private chats.                                                                                                                                                                                                                                     |
| Uploaded files                | Local and S3 handlers require a registered attachment and owner, current internal-share recipient or valid public-share permission. Unknown files fail closed. Ordinary export downloads require the requesting user plus an exact-path, five-minute grant; other temporary files remain admin-only. Attachment writes validate ownership before mutations and bind atomically with the note write. Password-protected shares require a scoped grant; expiry, recycling and revocation are checked on each application request.                                                                                                                                                           |
| Uploaded active content       | HTML, SVG and other active formats are forced to download as `application/octet-stream`. Responses add sandbox CSP, `nosniff`, no-referrer and private/no-store caching. Safe image/audio/video/PDF rendering remains available. Plaintext password persistence is removed, including cleanup of the legacy browser value.                                                                                                                             |
| Two-factor login              | The first factor issues a random, account-bound challenge with a five-minute lifetime and five verification attempts. Atomic session-table updates enforce cross-process attempt consumption and single use. The verification route additionally allows at most 60 requests per IP per five minutes per process. The legacy password-only API refuses login when 2FA is enabled. Local and OAuth clients submit the challenge.                         |
| SSRF                          | Link previews require login, accept only public HTTP(S) destinations, validate every DNS answer and redirect, and pin the validated address to the socket. DNS, queue wait, total request duration, response size and redirects are bounded by an absolute deadline; expired queued work cannot open a socket. Secondary oEmbed requests are disabled. Proxy diagnostics require superadmin, accept only the fixed Google/Baidu/Bing test URLs, and do not follow redirects. The URL-upload handler uses the same guarded transport. |
| Plugin installation           | Install/uninstall require superadmin. Plugin names, GitHub repository URLs, archive paths and symlinks are validated before writes or cleanup. Invalid requests and duplicate-version requests preserve existing files. Extraction streams and archive handles are closed on failure.                                                                                                                                                                  |
| MCP stdio                     | Stdio execution is denied unless the server operator approves the exact command, arguments and environment. This applies to create/update and runtime use of already-saved configurations. Child processes no longer inherit the application's entire environment. The former interpreter/metacharacter filter is removed.                                                                                                                             |
| RSS/Atom                      | Absolute link origins come from the configured application URL, with private/no-store responses; request Host/Origin cannot rewrite them. This hardens the confirmed reflection without asserting the unproven cache-poisoning/private-note claims.                                                                                                                                                                                                    |

## Compatibility and configuration

- No schema, migration or seed source is changed. Existing startup seed behavior can still write legacy ownership/directory/font data; unchanged DDL does not imply zero runtime writes. Pending 2FA challenges reuse the existing `session` table. Cleanup runs on a real first-factor login; no timer, worker or idle database polling is added.
- Custom 2FA clients must pass the new `challenge` returned by `/api/auth/login` to `/api/auth/verify-2fa`. OAuth pending challenges use the URL fragment and are cleared from the address bar after intake. Refresh restores only a valid unexpired saved challenge; no bearer profile request is required before the second factor. Old pending logins must restart from the first factor.
- Media and download clients merge URL parameters, preserving share/export grants and fragments. Export ZIPs use independent random work directories; mixed Local/S3 attachments are read according to their stored path, without forwarding credentials to the caller-supplied base URL.
- Protected shared attachments use five-minute, note-bound signed links. Changing the share password or share URL invalidates those grants. Reload the shared page to obtain fresh links after expiry. New S3 presigns also expire after five minutes; already-issued presigns remain valid until their original expiry or storage credentials are revoked.
- Set `NEXT_PUBLIC_BASE_URL` or `NEXTAUTH_URL` to the externally accessible application URL for RSS/Atom links. The fallback is `http://localhost:1111`.
- Stdio is disabled by default. Operators who need it set `BLINKO_MCP_STDIO_ALLOWLIST` to a JSON array of exact tuples, for example `[{"command":"node","args":["/opt/blinko-mcp/server.js"],"env":{}}]`. Browser configuration must match an approved tuple exactly. Approve only operator-controlled programs and environment values. HTTP MCP transports are unchanged.
- Guarded previews and URL uploads connect directly to the validated public address. They do not use a configured proxy that could resolve or redirect the destination differently. Proxy diagnostics retain their explicit proxy path.
- Purge old uploaded-file responses from any application-origin CDN/shared cache when releasing this patch. New cache headers cannot retract responses that were previously cached publicly.
- The macOS build keeps the optional native `fsevents` module external, consistent with the existing native-module build strategy.

## Verification

Run `cd server && bun run test:security`. Suites execute in separate processes because Bun module mocks are process-wide. Tests use temporary files, mocked database/storage/remote transports and ephemeral loopback HTTP servers. They do not connect to production, run migrations, create accounts, or start the application's background jobs.

The suites cover real tRPC authorization, Express login/file/S3/RSS routes, public-destination transport, plugin extraction and MCP runtime policy. They include first-factor omission, replay/concurrency, cross-account requests, password/expired/revoked shares, active-content response headers, redirect/DNS rebinding, traversal and symlink failures, and zero idle queries in the new challenge logic.

Validation on 2026-11-03: all 154 security regression tests pass across 14 isolated suites. Frontend Vite/PWA and backend production bundles pass. Standalone new policy/helpers pass targeted strict TypeScript checks; full server TypeScript validation remains incomplete (the previous 4GB run exhausted its heap and the 8GB retry did not finish).

A separate integration harness applied the original 30 migrations to an isolated PostgreSQL 14.23 database, inserted 7 synthetic accounts and 10,007 old-format notes, and verified real Prisma/Express authentication, file access, attachment writes, sharing and export mutations. The patched migration deploy has no pending migrations. Foreign explicit/Markdown attachments fail before note/history/tag writes; internal read/editor recipients work until revoked. Each Markdown/CSV/JSON export downloads for its owner and rejects another user, anonymous requests and missing/tampered grants. The browser logged in as the ordinary fixed `koray` account, retained its session after refresh/backend restart, rendered old notes, and downloaded a real JSON ZIP containing 5,005 own notes and zero other-user fixtures. An anonymous browser unlocked a password share and loaded its inline/fullscreen image with the share grant intact.

The harness isolates AI and unrelated import modules and never starts application job workers. It is not a full deployment, external OAuth-provider, live S3 or native Tauri acceptance. Passing these tests does not assign CVEs or close GitHub advisories. A broad release still needs deployment-specific acceptance and rollback preparation.

Additional verification on 2026-11-04: 165 tests pass across 15 suites. The production MCP transport factory and real SDK launch an exactly approved harmless local child without inheriting database/signing secrets; inline-execution and environment changes fail before spawn. Public HTML/SVG/XHTML/XML/JS stay inert downloads even when inline/thumbnail options are requested. RSS/Atom origins ignore individual Host, Origin and forwarded-header inputs. The transport fixture does not replace full production MCP handshake acceptance; HTTP suites still isolate database/feed dependencies. No runtime source changed in this verification follow-up.
